# Codex + Jev v1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Track evidence in `.superpowers/sdd/codex-jev-v1/progress.md`.

**Goal:** Ship a portable internal v1 with four Codex skills, a reusable review core, a thin CLI/MCP host and verified correctness fixes.

**Architecture:** `JevReview.Core` owns collection, typed requests, judging, policy and artifacts. CLI and MCP map their inputs into the same request. A versioned ZIP and project installer carry the runtime, skills and explicit configuration.

**Tech Stack:** C#/.NET 10 (SDK 10.0.303), xUnit, PowerShell 7; no new runtime dependencies.

**Spec:** The detailed seven-step plan in the conversation, extended by the user's instruction to refactor and remove proven dead code. See `docs/architecture.md` for the resulting boundaries and references.

## Global Constraints

- Preserve existing user changes; work on `codex/refactor-v1` in the ignored worktree.
- Keep wire artifacts, labels, Git semantics and CLI options compatible.
- Freeze rubric/policy before collecting input; preserve every terminal item and the accounting invariant.
- Offline checks only; never expose credentials or review payloads.
- Explicit skill invocation; no hidden keyword matcher or reasoning-effort override.
- No automatic merge, push, public publication or license selection.

## Review Focus

- Bracket/Unicode Git paths must yield one matching file per item.
- Linked roots, ancestors and output segments must be rejected before I/O.
- Malformed MCP initialization and requests before readiness must leave the host usable.
- Installation collisions, WhatIf and paths containing spaces must preserve existing files.
- A packaged runtime must operate outside the source checkout and contain no gold or user files.
